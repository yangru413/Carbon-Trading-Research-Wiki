## P1 碳交易配對研究如何進行？

教學問題：研究什麼？每一步要留下什麼？

在交易條件與供需限制下，尋找可比較的配對方案。

流程：研究問題 → 資料 → 模型 → 搜尋方法 → 實驗評估

- 配對要回答「向誰交易、交易多少」；圖中實線是其中一組安排，虛線代表其他候選關係。
- 先界定商品、參與者與供需，再選搜尋方法；數量吻合仍須檢查資格與交易條件。
- 研究留下可比較的方案、目標值與假設，才能說明某種安排為何值得選擇。

圖說：本站自製配對示意，依Wiki研究問題整理；企業與連線為假設，不是真實交易。

懶人包：先定義研究問題，再依資料建立模型，選方法並檢查證據。

來源：本站依Wiki研究導讀及CM03 §3.2.1整理，非已完成實證；比較流程依Beiranvand等人（2017）。

## P2 配額移轉，不等於實際減排

教學問題：為什麼會出現交易需求？

總量管制與交易結合排放額度限制與配額流通；額度不足可能形成購買需求。

- 甲需涵蓋100、持有80單位，可能缺20；乙需涵蓋60、持有80單位，可能有20餘額。圖中數字是教學假設。
- 取得配額可補足履約所需額度；它改變持有量，不能據此說企業已減少相同數量的排放。
- 餘額不等於出售意願。研究還要對齊配額種類、帳戶資格與制度期間；2020樣本應先對照EU ETS第三期。

懶人包：配額移轉改變持有量；實際減排需要排放變化的證據。

來源：European Commission，About the EU ETS及EU ETS歷史（2025）；United Nations（1998），Article 17。甲乙數字沿用Wiki自製示意。

Wiki：carbon-basics.html；eu-ets-history.html

## P3 配對方案要同時比較多種目標

教學問題：向誰交易、交易多少，怎樣才算更好？

CM03第二年規劃四個方向，這是研究提案中的目標，尚不是實驗成果。

- 買方成本：希望較低：比較買方取得所需單位的總成本；價格與費用的資料口徑須先說明。
- 賣方利潤：希望較高：比較賣方的利潤；不能把移轉數量直接當成收益或利潤。
- 永續聲譽總和：希望較高：計畫連結第一年的企業永續評估，不是交易紀錄中現成的評分。
- 配對數：希望較多：比較成立的配對數量；是否配對與交易多少是不同的決策。
- 示意：A成本80、利潤20；B成本90、利潤30。A成本較低、B利潤較高，兩者互不支配。
- Pareto支配指所有目標都不差、至少一項較好；不能在未說明偏好前，把四個目標任意合成一個分數。

懶人包：成本、利潤、聲譽與配對數可能互相取捨，不一定只有一個最好方案。

來源：CM03，Theme 2、§3.2.1及Pareto說明；A／B數字沿用Wiki教學假設，非價格或效能結果。

Wiki：cm03.html#objectives；pareto.html

## P4 先整理資料，再說它能支持什麼

教學問題：哪些欄位可用，哪些資訊仍然缺少？

流程：保留原始版本 → 對照欄位與單位 → 檢查ID與粒度 → 建立研究樣本

- 可能已有：帳戶、日期、交易ID、單位種類與數量，可用於核對移轉對象、時間及樣本範圍；先比對自身版本的欄位。
- 不能直接假定：成交價、當時供需、資格、聲譽與偏好，需要另找依據；EUTL移轉紀錄不等於逐筆買賣成交資料。
- 同一交易ID可能拆成多列單位區塊，應對照ID、單位與數量後再彙整，不能直接當重複資料刪除。
- 日期欄不直接等於簽約時間；樣本的時區、交易類別與商品種類，都應先核對再篩選。

產出成果：可追溯的樣本、欄位對照與清理規則。

來源：Abrell（2024），§1、附錄A.3–A.4；流程為本站整理，不代表本機全檔已完成清洗。

Wiki：sources.html；reading-eutl-database.html

## P5 模型連起資料、決策與限制

教學問題：如何把資料變成可以求解的問題？

流程：輸入資料 → 配對／交易量 → 資格與供需限制 → 計算各目標

- 先決定變數表示「是否配對」還是「交易多少」，再定義資格、供給上限與需求條件；同名符號不保證同義。
- 價格、聲譽等輸入要註明是觀測值、代理或模擬。日價格若當代理，須交代商品、時區、可觀察時間，並檢查替代口徑是否改變結果。

練習題：上午做配對，能直接把當天收盤價當已知資訊嗎？
答案：若模擬當時決策，收盤價尚不可觀察；需改用當時可取得的資訊，或另交代研究假設。

產出成果：明列變數、目標、限制與假設的模型版本。

來源：本站依CM03模型疑義與Wiki價格頁整理；流程是教學框架，非已核定模型。

Wiki：cm03.html#questions；sources.html#price

## P6 GA：重組一群候選方案

教學問題：新方案如何產生，又怎麼留下？

基因演算法（Genetic Algorithm, GA）把多個候選方案組成族群。先定義編碼與評估方式，再選親代，透過交配交換片段、突變改動個別位置，最後決定哪些方案留到下一代。碳交易使用前，仍須把配對、交易量與供需限制對應到表示法。

流程：評估族群 → 選親代 → 交配／突變 → 評估與選存活者

- 每個1代表選一項，最多選兩項；1111即使分數較高，仍因選了四項而不可行。
- 新字串不保證更好；必須重新計算目標並檢查限制。

產出成果：候選方案與目標值；不能宣稱保證最佳。

來源：Eiben與Schoenauer（2002），§2、§4–5；流程為Wiki自製概念整理，不是EMOBET完整實作。

## P7 ACO：逐步構造候選方案

教學問題：搜尋記憶如何影響下一次選擇？

蟻群最佳化（Ant Colony Optimization, ACO）的早期Ant System，讓人工螞蟻逐步構造方案。資訊素代表搜尋記憶，啟發式資訊提供選擇線索，兩者引導機率選擇。若用於配對，可先排除不符資格或供給條件的對象，再組成候選方案。

流程：合法選項 → 逐步構造 → 評估方案 → 更新資訊素

- 圖示為旅行推銷員問題（TSP）：連接城市形成巡迴，完成後評估路線再更新資訊素。
- GA重組既有方案；ACO逐步構造。碳交易仍須另定編碼、評分與供需限制。

## P8 公平比較之前，先檢查可行性

教學問題：怎麼知道方法有用，而不是只是跑出答案？

- 先驗可行性：逐項核對資格、供需與數量。右圖乙最多供10；方案B向乙取11，即使總量滿足12也不可行。
- 再比表現：使用相同測試情境與評估尺度，列出參數、計算預算及停止條件；隨機方法需記錄重複試驗設定。
- 限制結論：同時報告可行性、目標值與耗時。小樣本可先用於流程檢查，不能由單次較好結果推論市場整體或方法普遍較好。

產出成果：可重現設定、比較結果與結論適用範圍。

來源：Beiranvand等人（2017），§1.2–§3，主要範圍為單目標；多目標評估與耗時安排見CM03 §3.2.3；圖為本站假設。

## P9 留下能讓下一屆重做的研究

教學問題：需要承接什麼，又要交付什麼？

- 第一年 → 輸入：索取指標定義、企業識別對照、版本與可用時間，才能連接永續評估與交易對象；此處是建議清單，不代表已交付。
- 第二年 → 配對：保存資料版本、清理規則、模型假設、候選解與評估紀錄，讓接手者知道輸入如何變成結果，並能重做同一流程。
- 第三年 → 後續研究：交付可追溯結果及其假設與限制，供後續規則研究參考；也可依計畫構想，探索如何以規則知識支援搜尋。

產出成果：有版本、定義與限制的交接材料。

來源：CM03 Theme 1–3；交接圖為本站依研究流程整理的建議。

Wiki：start.html；research-methodology.html

## P10 研究不是直線：失敗就回到原因

教學問題：在哪裡退回？回去要改什麼？

流程：問題 → 資料 → 模型 → 方法 → 實驗

- 資料不足：回到來源與資料：補讀、核對欄位或改樣本。先辨認缺少的是觀測、版本還是定義，再決定是否採用代理資料。
- 方案不可行：回到模型與方法：逐項核對限制、編碼及處理方式；產生候選方案後，仍要重新檢查是否可行。
- 比較不公平：回到實驗設定：對齊測試情境、計算預算與指標。不能只挑單次最好結果，忽略其他執行的差異。
- 這些回頭修正就是研究的loop；每次修改後重查原問題及受影響項目，保存改了什麼、依據與原因。
- 資料、模型與比較條件先檢查清楚，才能避免把資料缺漏或設定差異誤認成演算法表現。

產出成果：可解釋的修正紀錄，而不只是最後一組答案。

來源：本站依Wiki研究導讀整理；比較原則參考Beiranvand等人（2017）。此為研究建議，非已執行碳交易實驗；與簡報製作graph不同。

Wiki：research-methodology.html；literature.html
