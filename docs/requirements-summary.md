# 碳交易Wiki：完整需求摘要

整理日：2026-11-23。依本次對話及既有專案規範彙整。較晚的明確要求優先；需求、已完成成果與待辦分開。此文件不是研究證據，也不宣稱所有長期要求均已完成。

## 一、作業交付
1. 自訂主題LLM Wiki，以先討論、後生成建立，至少ingest五篇資料。
2. 以Wiki為知識來源，製作可實際瀏覽的教學HTML簡報，使不熟悉主題者理解基本概念。
3. 說明loop／graph，包含資料取得、Wiki查詢、整理、檢查、產出及退回修改；回答哪些步驟重複、哪裡檢查／重做、為什麼這樣設計。
4. 提供一次真實執行及檢查紀錄，反思出錯節點、檢查前移與workflow調整，不虛構失敗、成效或完整審閱。
5. 繳交主題介紹、Wiki成果／連結、簡報連結、流程圖／文字、執行紀錄與反思。
6. 使用者自行製作Word並轉PDF；AI僅提供參考大綱，不代做Word／PDF。原定期限為台灣時間2026-11-23（一），未提供確切時刻。

## 二、主題、讀者與研究定位
- 名稱固定「碳交易 Wiki」，不加副標題。
- 讀者是剛起步研究的使用者，以及接第三年的學弟妹；基本程式與大學數學基礎可預設，但不熟悉碳交易、EUTL與最佳化方法。
- 教學主軸為「我們研究什麼、如何進行研究」，不是僅介紹如何開始。研究目的與基礎知識必須有，方法論為重點。
- 第二年碳交易與演算法為中心向外擴展，說明第一年可提供的輸入及第二年如何支援第三年。
- CM03提供主題與方向，不是唯一正確模型或已完成成果。資料集、演算法可重新搜尋與評估。
- 第一年度成果尚未取得；索取清單與自行建立項目只能標成建議／預期，不能說已交付。
- 價格、可靠度／環保度／成本、權重與樣本可行性屬待研究問題，不阻擋建站。缺資料不是自動沒有約束。
- 使用者曾回報NOTESD特定時段／類別樣本，尚未全檔核實；實際樣本、帳戶資訊與私人研究進度不公開，公開只說一般化方法與限制。

## 三、Wiki內容與頁型
- 雙入口：研究導讀＋主題查閱。導讀串起問題、制度、資料、模型、方法、評估與交接；熟悉者可直接查主題。
- 頁型：主題導讀、概念／方法文章、文獻摘要、比較整理；疑義放相關文章，補充內容放延伸閱讀，不讓私人進度占公開正文。
- 核心組別：研究引言／流程／方法論、碳交易意義與起源、EU ETS制度與法規、資料清洗與欄位、GA與ACO。
- GA與ACO是教授提過的候選方法：簡介為主，比喻與微應用為輔；保留各自詳細機制與應用文章的延伸空間，不造空頁或假連結。
- 原先要求每篇主要文章3–5篇文獻。使用者後來明確要求先以作業為優先、額外要求暫緩；此項保留為後續補強，不當作v1已完成條件。
- 原有9頁不得因擴充被刪除；新增內容保留有效引用、穩定網址及返回入口。文章須有標題、性質、摘要、正文、來源、更新日，必要時補單位、符號、假設及限制。

## 四、語言、證據與素材
- 中性繁體中文，先白話再正式；術語首次附英文與縮寫，書目保留原文。避免賣課、菜鳥、命令式文案。
- 最終確認：外部知識每段作者年份引用；公式、圖表、直接引文附精確位置；文末APA書目。較早「每節統一列引用」已被取代。
- 記錄題目、作者、年份、出處／DOI、版本、查閱日、實讀範圍、解決問題、方法、重點、限制與寫入位置。只列流程、不交代論文問題與方法不可接受。
- CM03摘要逐段保留章節與起句定位；事實、提案、解讀、示意、結果分開標示，不補造數字、模型、引文或成效。
- arXiv等合法可取得論文保存PDF與出處，下載預設私人保存；無法取得如實說明，不冒充全文核讀。
- 文獻矛盾並列，核對年代、資料、定義及假設；無法判定保留爭議，影響研究取捨再問使用者。
- 圖像偏好相關真實影像或簡約插畫；先確認用途及授權，保留來源／自製／AI／改繪身分及假設。引用不等於重製權。
- assets/已存在，沿用及擴充，不重建另一套；本批簡報實際沿用自製示意，未宣稱取得京都會議新聞照片。
- 不確定學術倫理／公開權限時逐項確認；既有授權內例行事項不反覆問。

## 五、LLM Wiki維護
- 參考使用者貼的Karpathy LLM Wiki模式：原始來源唯讀、知識持續整合、規則約束維護，借用ingest／query／lint與累積紀錄。
- 沿用HTML、JSON與既有建置，不為模仿而強制轉Markdown、導入Obsidian、RAG、向量庫或付費API。
- 初期逐篇討論的選擇，已被2026-11-21「一次五篇，集中討論後整合」取代。
- Ingest不只下載或登記書目：建立摘要、更新相關舊文、補引用與交叉連結，檢查後記錄實際操作。
- 查詢先看Wiki索引與相關頁，證據不足明示；問答回寫先提出建議，不任意擴寫。
- 後續產出以教學HTML簡報為主，其他成果另提需求。
- 更新理想為手動＋定期，穩定後部分主題自動；頻率／範圍未定，未建自動排程。
- Lint涵蓋連結、引用支持程度、孤立頁、交叉矛盾、過時資訊、缺漏、素材權限與隱私；語意審閱不等於程式通過，尚未完整做到的項目要保留限制。

## 六、投影片與graph
- 適合自行瀏覽，簡短易懂，可逐頁／故事式；目前選10頁逐頁，細節連回Wiki。
- 目前大綱：研究全貌 → 基本概念 → 配對與多目標 → 資料清理 → 模型假設 → GA → ACO → 評估 → 年度銜接 → 流程回顧。
- 按graph執行：目標 → Wiki／來源 → 大綱確認 → 逐頁稿／內容核對 → HTML → 實測 → 使用者試讀。
- 各階段必須說明做什麼、查什麼；退回要指出原因、修改位置及重新檢查項目。研究方法的graph與製作投影片的graph分開。
- 圖表主線由上往下，保留主標題；最新要求刪副標題、刪最下方最小備註，只留一句簡述loop。自製身分另在來源文件記錄。
- 大綱與逐頁內容分開保存，先確認大綱再展開內容。使用者要求照流程重製已作為本次大綱執行授權，不捏造逐頁人工驗收。
- 固定畫面兩側換頁，無須滑到底；底部重複上一頁／下一頁已移除，保留頁碼、跳頁、鍵盤、全文及列印。
- 桌機、手機、首尾、跳頁、鍵盤、圖像、連結、全文、列印與無JS需實測；測試通過不代表使用者已確認教學易懂。

## 七、視覺與技術
- 保留米白、深綠、自然色與雜誌式風格，現有雛型接近理想，不大改視覺。
- 圓角矩形卡片桌機四欄，平板／手機減欄，灰色內容狀態；展開推移後續卡片、簡潔動畫並尊重減少動態設定。
- 標題進文章、卡片內文展開；延伸數量隨實質內容，不固定三項。適合圖解處加有來源圖像，不能只有裝飾。
- 無框架靜態HTML/CSS/JS，可部署GitHub Pages，無後端、登入、金鑰或付費服務依賴。
- 正文／登錄／來源／共用CSS／JS／建置產物分工，原始研究檔唯讀；公開檢查不得強制依賴私人原檔。
